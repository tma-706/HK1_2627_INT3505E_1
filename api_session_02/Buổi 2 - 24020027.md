1. Lấy danh sách issue của một repository

- Endpoint: GET /repos/{owner}/{repo}/issues
- Method: GET - dùng để đọc danh sách issue.
- Status code:
  + 200 OK: lấy danh sách thành công.
  + 301 Moved Permanently: resource đã chuyển.
  + 404 Not Found: repository không tồn tại hoặc không truy cập được.
  + 422 Unprocessable Entity: tham số/request không hợp lệ.
- Headers:
  + Accept: application/vnd.github+json
  + Authorization: Bearer <TOKEN> nếu cần xác thực.
  + X-GitHub-Api-Version: chỉ định phiên bản API.


2. Tạo một issue mới

- Endpoint: POST /repos/{owner}/{repo}/issues
- Method: POST - dùng để tạo issue mới.
- Status code:
  + 201 Created: tạo issue thành công.
  + 400 Bad Request: request không hợp lệ.
  + 403 Forbidden: không đủ quyền.
  + 404 Not Found: repository không tồn tại.
  + 410 Gone: chức năng issue đã bị tắt.
  + 422 Unprocessable Entity: dữ liệu không hợp lệ.
  + 503 Service Unavailable: server tạm thời không phục vụ.
- Headers:
  + Accept: application/vnd.github+json
  + Authorization: Bearer <TOKEN>
  + X-GitHub-Api-Version: chỉ định phiên bản API.
  + Content-Type: application/json


3. Lấy thông tin một issue cụ thể

- Endpoint: GET /repos/{owner}/{repo}/issues/{issue_number}
- Method: GET - dùng để đọc một issue cụ thể.
- Status code:
  + 200 OK: lấy issue thành công.
  + 301 Moved Permanently: issue đã được chuyển.
  + 304 Not Modified: dữ liệu chưa thay đổi, có thể dùng bản cache.
  + 404 Not Found: issue không tồn tại hoặc không truy cập được.
  + 410 Gone: issue đã bị xóa.
- Headers:
  + Accept: application/vnd.github+json
  + Authorization: Bearer <TOKEN>
  + X-GitHub-Api-Version: chỉ định phiên bản API.


4. Cập nhật một issue

- Endpoint: PATCH /repos/{owner}/{repo}/issues/{issue_number}
- Method: PATCH - dùng để cập nhật một phần issue như title, body, state, labels,...
- Status code:
  + 200 OK: cập nhật thành công.
  + 301 Moved Permanently: issue đã được chuyển.
  + 403 Forbidden: không đủ quyền cập nhật.
  + 404 Not Found: issue không tồn tại.
  + 410 Gone: issue đã bị xóa.
  + 422 Unprocessable Entity: dữ liệu không hợp lệ.
  + 503 Service Unavailable: server tạm thời không phục vụ.
- Headers:
  + Accept: application/vnd.github+json
  + Authorization: Bearer <TOKEN>
  + X-GitHub-Api-Version: chỉ định phiên bản API.
  + Content-Type: application/json


5. Khóa một issue

- Endpoint: PUT /repos/{owner}/{repo}/issues/{issue_number}/lock
- Method: PUT - dùng để đặt trạng thái khóa cho issue.
- Status code:
  + 204 No Content: khóa thành công, không cần trả body.
  + 403 Forbidden: không đủ quyền.
  + 404 Not Found: issue không tồn tại.
  + 410 Gone: issue không còn tồn tại.
  + 422 Unprocessable Entity: dữ liệu không hợp lệ.
- Headers:
  + Accept: application/vnd.github+json
  + Authorization: Bearer <TOKEN>
  + X-GitHub-Api-Version: chỉ định phiên bản API.
  + Content-Length: 0 nếu không gửi body.


→ Các endpoint trên có thể xem là RESTful vì nhìn chung đáp ứng các ràng buộc chính của REST:
  * Client–Server: client và server được tách biệt, client chỉ cần giao tiếp với GitHub thông qua API.
  * Stateless: mỗi request chứa đủ thông tin cần thiết như URI, headers và token xác thực, không phụ thuộc vào request trước.
  * Cacheable: API hỗ trợ cơ chế cache của HTTP như 304 Not Modified và ETag.
  * Uniform Interface: các endpoint dùng URI để định danh resource, kết hợp thống nhất với HTTP method, status code, headers và JSON representation.
  * Layered System: client không cần biết request có đi qua gateway, proxy, cache hay các lớp trung gian khác hay không.
  
⇒ Vì vậy, 5 endpoint trên nhìn chung phù hợp với kiến trúc REST.
